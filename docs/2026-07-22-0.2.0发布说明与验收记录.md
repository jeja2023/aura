# Aura 0.2.0 发布说明与验收记录

发布日期：2026-07-22

## 1. 发布结论

`0.2.0` 将 Aura 从仅调用固定 AI 能力的业务系统，扩展为可对接通用媒体解析平台的业务中枢。Aura 负责选择需要解析的图片、视频和视频流点位，下发任务或订阅；外部解析提供方负责推理并以标准事件回推；Aura 可靠接收结果，完成业务事实、向量检索、空间关系和告警研判投影。

本版本不包含任何特定厂商客户端。提供方通过统一接口、标准事件和可插拔认证接入。

版本号从 `0.1.33` 升级为 `0.2.0`，原因是新增了完整的媒体解析子系统、跨存储数据模型和生产运维契约，属于 pre-1.0 阶段的显著能力升级。

## 2. 数据存储职责

| 组件 | 主要职责 | 数据地位 | 故障时的系统行为 |
| --- | --- | --- | --- |
| PostgreSQL | 租户配置、提供方、管线、媒体源、任务、Inbox/Outbox、标准事件、业务事实、审计和迁移状态 | 唯一业务权威源 | 不确认新回调，由提供方重投；已提交事务保持一致 |
| PostgreSQL + pgvector | 512 维特征向量、模型版本、来源追溯、租户过滤、相似度检索 | 权威向量索引 | 结构化事件仍可入库，向量检索返回明确不可用状态 |
| ArangoDB | 空间、设备、人员、轨迹、访问和共现关系的多跳遍历与图查询 | PostgreSQL 的可重建派生图 | PostgreSQL 继续写入，Outbox 积压；恢复后自动追平或全量重建 |

核心约束：

- PostgreSQL 与业务事实保持同一事务边界。
- pgvector 保存可追溯到租户、模型和业务对象的权威向量。
- ArangoDB 不保存唯一业务事实，不参与业务请求内的同步双写。
- PostgreSQL Outbox 是写入 ArangoDB 的唯一增量通道。
- 图数据库损坏或丢失时，可使用 PostgreSQL 权威数据执行全量重建。

## 3. 本版本交付范围

### 3.1 通用解析提供方

- `IMediaAnalysisProvider` 扩展接口和标准 HTTP 适配器。
- 图片同步、视频异步轮询、视频流持续订阅三类工作模式。
- 提供方能力发现、任务提交、状态查询、结果和制品拉取。
- 无认证、HMAC、Bearer、OAuth2 Client Credentials 和 mTLS。
- 提供方级并发限制、连接/尝试/总超时、重试、熔断和请求/响应限制。
- 出站凭据 `secret_ref` 与入站 `webhook_secret_ref` 独立配置。
- 通用模拟器及超时、失败、重复、乱序等故障注入。

### 3.2 可靠事件入口

- 单条和批量 Webhook 入口。
- HMAC 签名、时间戳窗口、nonce 防重放和常量时间比较。
- 持久化 Inbox、租约、`SKIP LOCKED` 并发消费、重试、死信和人工重放。
- 事件 ID、序列号、重复和乱序控制。
- 标准事件、业务事实和图 Outbox 同事务提交。

### 3.3 业务事实与制品

- 检测结果、轨迹映射、抓拍、身份候选、ROI、行为和告警/研判事实。
- 提供方轨迹、Aura 轨迹、实体和向量标识分离。
- 向量模型版本、维度、距离度量和来源元数据。
- 制品受控拉取、重定向限制、类型/大小校验、归档重试和死信。

### 3.4 pgvector

- 512 维向量表、HNSW 索引和租户/模型过滤。
- 默认 `ReadEngine=pgvector`、`WriteMode=pgvector`。
- 默认 `AllowLegacyReadFallback=false`。
- 旧向量导出、回填、检查点、双写补偿和影子检索评测。
- 写入、搜索、迁移和补偿操作的指标与管理接口。

### 3.5 ArangoDB 关系图

- 独立图数据库、账号、命名图、顶点集合和边集合初始化。
- 租户隔离且确定性的顶点/边键。
- Outbox 增量投影、检查点、重试、死信、重放和全量重建。
- 摄像头可达性和路径、人员访问和共现、房间当前人员查询。
- 查询深度、结果数、运行时间和响应体积保护。

### 3.6 管理与权限

- 提供方、管线、媒体源、订阅、任务、Inbox、制品、向量、图和 readiness API。
- 对应的媒体解析管理页面和导航入口。
- 所有新接口执行统一租户范围校验。
- 全局提供方由超级管理员管理；楼栋管理员默认拥有本租户常用媒体操作和图查询权限。
- 事件重放、向量迁移和图管理保持显式高权限控制。

### 3.7 可观测性

- 提供方调用结果、延迟和超时分类。
- Webhook 认证与接收结果、Inbox 传输延迟和处理延迟。
- 分析任务结果和耗时、队列积压及最老事件年龄。
- pgvector 检索、图投影/查询/重建和 Worker 心跳。
- 全局 readiness 汇总媒体解析平台及其后台 Worker 状态。

## 4. 数据库升级

本版本新增迁移 `015` 至 `024`：

| 版本 | 内容 |
| --- | --- |
| `015` | 媒体解析控制面 |
| `016` | Inbox、Outbox 和事件重放 |
| `017` | pgvector 扩展、512 维向量和 HNSW 索引 |
| `018` | 租户安全的空间拓扑约束与索引 |
| `019` | 图投影和全量重建检查点 |
| `020` | 标准化业务事实、幂等约束、Worker 心跳和向量迁移证据 |
| `021` | 向量双写失败补偿队列 |
| `022` | 制品归档租约、重试和死信 |
| `023` | 提供方出站凭据与 Webhook 凭据分离 |
| `024` | 媒体解析和图查询默认权限 |

从 `0.1.33` 升级：

1. 备份 PostgreSQL，并验证备份文件可读取。
2. 确保目标 PostgreSQL 镜像已替换为支持 pgvector 的 PostgreSQL 16 镜像。
3. 检查迁移历史：

```powershell
dotnet run --project backend/Aura.DbMigrator -- status --fail-on-drift
```

4. 在维护窗口执行增量迁移：

```powershell
dotnet run --project backend/Aura.DbMigrator -- migrate --command-timeout 300 --lock-timeout 60
```

5. 确认无 pending 和 drift：

```powershell
dotnet run --project backend/Aura.DbMigrator -- status --fail-on-pending --fail-on-drift
```

已有数据库禁止执行 `bootstrap`。该命令只用于空数据库初始化。

## 5. 重要配置变化

- `POSTGRES_IMAGE` 应使用 `pgvector/pgvector:pg16` 或内部批准的等价镜像。
- `VECTOR_INDEX_READ_ENGINE=pgvector`。
- `VECTOR_INDEX_WRITE_MODE=pgvector`。
- `VECTOR_INDEX_ALLOW_LEGACY_READ_FALLBACK=false`。
- Docker 部署默认 `GRAPH_ENABLED=true`，需要配置独立的 `ARANGO_GRAPH_DB`、`ARANGO_GRAPH_USER` 和 `ARANGO_GRAPH_PASSWORD`。
- 提供方出站访问必须配置允许的主机；私网地址和 HTTP 访问需要分别显式开启。
- 提供方 `secret_ref` 和 `webhook_secret_ref` 必须指向环境变量、配置或 Secret，不得填写明文密钥。
- 对公网接收事件前，必须把 `MEDIA_ANALYSIS_PUBLIC_WEBHOOK_URL` 设置为提供方可访问的 Aura HTTPS 地址。
- `media-provider-simulator` 仅属于 `dev-tools` profile，不应作为生产解析服务启用。

## 8. 发布和回滚

发布镜像统一使用 `v0.2.0`，包括 API、AI 和通用提供方模拟器；默认离线归档文件为 `aura-images-v0.2.0.tar`。模拟器镜像仅供测试环境选择性启用。

建议发布顺序：

1. 备份 PostgreSQL 和当前配置文件。
2. 准备 pgvector PostgreSQL 镜像、ArangoDB 镜像及 `v0.2.0` 业务镜像。
3. 执行数据库迁移并核对状态。
4. 启动 API，检查 pgvector、媒体 Worker 和图投影 readiness。
5. 先接入模拟器或测试提供方，再逐个启用生产提供方和视频流订阅。
6. 观察 Inbox/Outbox 积压、死信、提供方错误率和图投影延迟。

回滚原则：

- 停止新任务和视频流订阅，保留 Inbox/Outbox 数据用于排查。
- 应用镜像可回退到上一版本，但数据库结构不使用反向 SQL 回滚。
- 需要完整数据库回退时，从发布前备份恢复，并执行迁移状态检查。
- ArangoDB 是派生数据，可清理后从 PostgreSQL 全量重建，不应以恢复图备份替代 PostgreSQL 恢复。
- pgvector 已是 `0.2.0` 默认权威向量库；只有在历史向量迁移数据和影子评测证据完整时，才允许短时开启旧索引回退。
