# Aura API 与数据迁移指南

0.3.0 保留原有抓拍、媒体分析、向量和图接口，并新增 `/api/commercial` 业务域。旧告警/工作流通过迁移作业生成统一事件和案件映射；迁移前后均保留 legacy id、映射状态和对账统计。调用方应逐步切换读取，不得长期双写两个权威状态。

## 升级顺序

1. 备份 PostgreSQL、对象元数据和当前配置，记录 0.2.0 镜像摘要与迁移状态。
2. 在副本环境执行 `Aura.DbMigrator status`，确保旧迁移无 unknown/drift。
3. 部署当前迁移器并执行 025-037；API 进程不会替代显式迁移。
4. 启动 API，校验 readiness、权限种子、租户作用域和原有接口。
5. 创建 legacy migration run，按批次导入、对账并只读切换；异常批次可恢复，不删除旧记录。
6. 完成工作台、外联消费者和通知通道回归后，才批准读路径切换。

## 0.4.0 安全升级要求

- 0.4.0 起，`/api/capture/push`、`/api/capture/sdk`、`/api/capture/onvif` 不再接受只覆盖设备和通道的旧签名；调用方必须按时间戳、nonce、设备/通道和原始请求体 SHA-256 生成新签名。默认时钟窗口为前后 300 秒，nonce 不得复用。
- 生产环境必须配置可用 Redis；防重放存储不可用时抓拍返回 `50312`，不得通过重试或代理绕过。
- 原 `/storage` 匿名文件链接不再有效。楼层图、抓拍图、媒体制品和移动证据必须携带有效会话并满足对应角色、权限和租户范围；证据导出继续使用专用下载 API。
- 生产环境必须为 .NET 的 `Ai:ApiKey` 和 AI 服务的 `AURA_API_KEY` 配置相同且至少 24 字符的随机密钥。路径型 AI 接口只有配置允许目录后才启用。
- 部署 API 前执行迁移 `037`，并确认 `nvr_device.last_seen_at` 与 `idx_nvr_device_status_last_seen` 已存在。

## 0.3.0 新增契约
- 事件/案件使用版本号进行乐观并发；冲突返回当前版本，客户端必须刷新后重试。
- 高风险操作先预览，再携带 preview token、确认短语、幂等键和 step-up 会话执行。
- 调查查询保存请求、结果摘要、来源和权限快照；受控自然语言只编译到允许的查询类型。
- OIDC、规则、AI 阈值、留存策略和服务画像均采用草稿、审批/发布和版本化状态。
- 移动草稿在服务端保存版本；冲突不覆盖远端，API/令牌/图片不进入 Service Worker 缓存。

回滚采用“恢复已验证备份，再运行对应版本应用”的方式。035 及之前迁移不提供破坏性 down 脚本；不能通过手工删表伪造版本回退。
