# 企业身份威胁模型与恢复手册

## 信任边界

浏览器、反向代理、Aura API、客户 IdP、PostgreSQL 与审计/通知通道分别视为独立信任边界。OIDC 只接受 Authorization Code + PKCE；issuer、audience、签名算法、JWKS 和 nonce/state 必须验证。claim 映射需先预览再双人批准，禁止以邮箱域或显示名自动授予超级管理员。

主要威胁包括登录事务重放、开放重定向、弱 claim 映射导致提权、会话撤销延迟、MFA 降级、高权限账号长期启用、IdP 中断和审计通道不可用。控制措施为短时登录事务、固定回调、PKCE、白名单签名算法、租户作用域权限、step-up、服务端会话撤销、不可变审计和应急告警。

## 应急账号

应急账号默认禁用，密钥保存在独立保管流程中，至少季度轮换和演练。启用必须说明原因，最长 60 分钟；成功登录后系统自动禁用并写入 Outbox 告警。演练必须证明启用、一次性使用、自动禁用、审计、通知和密钥轮换六步均可完成。

## IdP 故障恢复

1. 确认是 IdP、网络、JWKS 还是映射故障，冻结映射变更。
2. 使用经批准的应急账号进入运行中心，不得临时开放本地普通账号绕过策略。
3. 校验最近身份配置变更和审计记录；必要时禁用故障提供方并撤销相关会话。
4. IdP 恢复后完成登录、MFA、权限、登出和撤销回归，再关闭应急窗口。
5. 轮换应急密钥并将时间线、影响、操作人和复盘链接附到事件/案件。

任何生产 IdP 在 `oidc_idp` 门禁未通过前保持 experimental。
