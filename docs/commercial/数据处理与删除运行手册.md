# 数据处理与删除运行手册

## 原则

PostgreSQL 是事件、案件、调查、证据元数据和生命周期状态的权威数据源；pgvector 是权威向量索引；ArangoDB 是可重建投影。租户隔离、用途限制、最小留存和法律保全优先于容量清理。对象存储删除与数据库删除必须通过作业状态对账，禁止仅删除数据库引用。

## 留存与法律保全

留存策略按租户和数据集版本化审批。命中法律保全的对象不得归档或删除；保全的创建、释放、理由、批准人和作用范围必须审计。生命周期预览先输出预计对象数与字节数，执行时使用相同策略版本和范围指纹。

## 删除流程

1. 验证租户、数据主体/业务范围、保全状态和批准引用。
2. 生成影响预览；高风险删除进入预览令牌、MFA step-up、二次确认和幂等键保护。
3. 权威记录归档删除后，为 PostgreSQL、pgvector、ArangoDB、Redis、对象存储、导出副本和备份到期分别建立投递；每个投递使用租约、重试和独立证明。
4. 失败项进入可重试状态，不把部分完成报告为成功；对象存储结果与权威记录对账。
5. 所有投递进入 `completed` 或有依据的 `blocked` 后才结束 Outbox；`blocked` 不是成功，恢复依赖后必须通过重放接口补齐。
6. 备份投递只记录不可变备份到期日，最长 35 天；不得通过在线删除流程改写不可变备份。
7. 完成后生成删除审计，不在报告中保留已删除的敏感正文、图片或向量。

删除投递可通过 `GET /api/v1/data-lifecycle/jobs/{jobId}/deletion-deliveries` 对账；依赖恢复后调用 `POST /api/v1/data-lifecycle/jobs/{jobId}/deletion-deliveries/replay?storeType=...`。ArangoDB 或 Redis 未配置时必须返回带原因的 `blocked`，禁止伪造空删除成功。

## 数据主体请求与退租

请求需验证身份和租户授权，记录接收、检索、保全冲突、批准、执行与回复时间。退租先导出合同约定数据，再撤销身份和令牌，执行留存/删除策略，验证备份到期处置，并输出不可逆删除和暂存保全项的清单。任何手工数据库删除均视为流程违规。
