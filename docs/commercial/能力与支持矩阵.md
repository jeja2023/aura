# Aura 0.3.0 能力与支持矩阵

本矩阵是销售、交付和升级的统一口径。`supported` 仅表示列出的组合已经取得对应版本证据；不在“认证目标”中的型号、固件、依赖版本或规模不得类推。现场证据由发布门禁报告和适配器认证运行记录引用。

| 能力 | 状态 | 认证目标 | 限制与放行条件 |
| --- | --- | --- | --- |
| 统一事件、案件、调查和证据导出 | supported | Aura API 0.3.0；PostgreSQL 16 + pgvector | 生产放行仍需目标规模、浏览器和备份恢复门禁 |
| 租户隔离、细粒度权限、MFA step-up | supported | 本地账户与内置角色 | 角色变更、高风险操作必须保留审计；超级管理员不能代替租户对象授权 |
| OIDC Authorization Code + PKCE | experimental | 标准发现文档/JWKS 接口 | 每个客户 IdP 的 issuer、签名、claim 映射、登出和应急恢复必须单独认证 |
| 应急账号 | supported | 本地一次性启用，最长 60 分钟 | 禁止常开；登录后自动禁用；季度演练、轮换和告警为硬要求 |
| 规则影子、灰度、抑制、熔断、回滚 | supported | 结构化事件条件与案件动作 | 自定义代码执行不在支持范围；发布前必须 dry-run/审批 |
| AI 评测、阈值、反馈和漂移 | supported | 持久化指标与人工反馈流程 | 模型上线仍受批准阈值和目标数据集门禁约束 |
| PostgreSQL 权威业务数据 | supported | PostgreSQL 16 | 只能通过增量迁移升级；空库可 bootstrap；恢复必须演练 |
| pgvector 权威向量索引 | supported | pgvector 0.8.x，512 维 HNSW | 支持规模由服务画像和目标硬件报告限定 |
| ArangoDB 可重建关系图 | experimental | ArangoDB 3.12.x | 必须取得真实集群投影、追平、重建、N 跳与最短路径证据后才能转 supported |
| 海康 ISAPI | experimental | 已有标准接入表面 | 只有八项检查、真实设备和报告 URI 齐全的具体型号/固件才可在认证记录中标记 certified |
| ONVIF | experimental | 抓拍接入契约 | 真实设备发现、认证、抓拍和故障恢复尚需型号级认证 |
| 大华设备 | planned | 无 | 页面或接口占位不构成产品支持 |
| C++ SDK 网关 | planned | 无 | 需客户 SDK、隔离网关、真机和升级回归证据 |
| 通用 HTTP 媒体解析提供方 | experimental | 标准任务/Webhook 契约与模拟器 | 每个真实提供方版本必须通过八项合同测试和真实服务报告 |
| Chromium/Edge 工作台 | experimental | 响应式商业工作台和 PWA 静态壳 | 目标版本、角色、桌面和窄屏矩阵通过后按交付画像标记 supported |
| 轻量移动处置 PWA | experimental | 我的待办、事件确认、案件评论/状态、在线拍照证据、定位授权、深链/扫码、推送订阅、弱网草稿冲突检测 | 不缓存 API 响应、令牌、图片或证据；照片只能在线上传；目标移动浏览器和[自托管 Web Push 网关](通知与Web%20Push网关.md)仍需现场门禁 |
| 托管服务计量与权益 | experimental | 租户权益、用量账本和成本聚合 | 0.3.0 不提供支付、开票或公有云多区域 SLA |

适配器只有当 `adapter_contract_run.status=passed`、八项检查全部通过、`environment.realDevice=true` 且存在报告 URI 时才可作为认证证据。能力状态变更必须更新数据库 `product_capability`、本文件、变更记录和发布门禁报告。
