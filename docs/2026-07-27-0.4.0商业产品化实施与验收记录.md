# Aura 0.4.0 商业产品化实施与验收记录

本记录对应 2026-07-27 发布的 Aura 0.4.0。该版本在 0.3.1 基线上完成全项目安全、数据一致性、重试可靠性和自动化测试加固。由于抓拍 HMAC 契约、私有文件访问方式和生产配置门禁发生不兼容变化，本次按次版本升级发布，不作为透明补丁部署。

## 变更范围

### 私有文件与权限

- 移除 `/storage` 匿名静态映射，新增经过身份、角色、细粒度权限和租户范围校验的受控文件端点。
- 通用文件路由拒绝证据导出、日志和运行时目录；证据导出继续经过授权、有效期、次数限制和审计完整的专用 API。
- 抓拍、楼层、媒体分析和移动证据文件按业务权限开放；非安全媒体类型强制下载，所有响应禁止公共缓存。

### 数据一致性与会话

- PostgreSQL 已配置时，旧仓储异常统一抛出数据不可用错误，不再以空数据、`false` 或 AppStore 内存状态伪造成功。
- 数据库异常统一映射为带追踪 ID 的 `503`；开发内存回退只在未配置数据库且显式允许时生效。
- 设备心跳状态和 `last_seen_at` 持久化，新增迁移 037 与查询索引。
- 鉴权会话增加短时 Redis 缓存；登出、停用、角色或资料变更、密码重置、用户删除及显式撤销会同步清除缓存。

### 抓拍安全与可靠重试

- 抓拍签名正文升级为 `deviceId\nchannelNo\ntimestamp\nnonce\nSHA256(rawBody)`，使用设备独立密钥执行 HMAC-SHA256。
- 时间戳窗口、nonce 格式和 Redis 原子防重放成为必检项；生产 Redis 故障时拒绝接收，避免安全降级。
- 重试任务采用 pending/processing、显式 ACK、启动恢复和原子重新入队；Redis 锁使用令牌比对释放并支持续租。
- 重新入队或 ACK 失败会保留任务和图片，不再误报重试已排队或提前删除重试载荷。

### AI 与工程治理

- 生产环境强制非占位 AI API Key，关闭接口文档，并默认禁用未配置目录的文件提取及数据集评测。
- 删除不参与生产构建的 `generated/` 旧源码、重复中间件和废弃服务，源码只保留一个权威实现。
- 新增受控存储、数据库故障语义、防重放和 AI 安全回归测试；前端新增 Playwright 桌面与移动端登录冒烟门禁。

## 不兼容升级项

1. 所有抓拍客户端必须增加 `X-Capture-Timestamp`、`X-Capture-Nonce`，并按原始请求字节计算新 `X-Signature`。
2. 依赖匿名 `/storage` URL 的外部调用必须改为携带 Aura 会话，证据导出必须调用专用下载 API。
3. 生产部署必须同时配置 `Ai:ApiKey` 与 `AURA_API_KEY`，且密钥一致、非占位并不少于 24 字符。
4. 生产抓拍必须具备 Redis；缺少 Redis 时接口按安全策略返回 `50312`。
5. 启动 0.4.0 API 前必须执行数据库迁移 037；回滚采用恢复已验证备份和旧版本应用的方式，不能手工删除字段伪造回退。

## 继承门禁

自动化通过不替代现场验收。真实 PostgreSQL/Redis/ArangoDB 集群、目标规模 pgvector、长时间积压恢复、备份恢复演练、Linux 离线镜像交付、客户 OIDC、通知/Web Push 网关、目标浏览器矩阵和真机适配器仍由 `scripts/ops/release-gate.*` 阻断。只有形成目标环境证据 URI 后，才能调整能力矩阵中的认证状态。
